# 新战斗模型与功法系统 · 规格

> 2026-11-12 · 依据：武器系统与功法系统职责重叠，砍掉武器；技能归功法；能量改为自然恢复；
> 平A 改为固定间隔；功法分七阶对应七层塔。

## 0. 一句话

**功法就是这个传奇的全部打法**：它决定平A 间隔与伤害、能量恢复速率、能放什么技能以及命中后的阵形动作。
构件只做一件事——把功法的纹路填上，决定这门功夫发挥几成。

---

## 1. 取舍（已定）

| 项 | 结论 |
|---|---|
| 武器系统 | **删除**。`WEAPONS`、`weaponId`、主手动作、主手终端全部移除 |
| 技能来源 | **功法自带**。每套功法 1~2 个招式 |
| 能量 | **自然恢复**，按秒累计；部分功法改写恢复规则 |
| 平A | **固定间隔 0.5s 起手**，功法可调 0.35~0.8s |
| 站位 | 四个身位都能释放所修招式；交战目标随当前阵形变化 |
| 稀有度 | **七阶**，对应七层塔；按「机制复杂度」分层，不是数值递增 |
| 招募 | 自带一阶微功法（占地 1~2 格）+ 2~3 个刻印，开局就能平A |

前锋优先承受直击。星火命中后可以与第二位互换，逐隙从后两位插到最前，回息在敌方攻击后与前方残血友军交换。

## 2. 战斗模型

### 2.1 时间轴

废弃行动条（原 gauge 阈值 60）。战斗变成一条纯时间轴：

```
t=0                  t=0.5               t=1.0
 │  平A                │  平A              │  ...
 │  平A 计时器 = attackInterval
 └─ 技能可以插在任意时刻，占 castTime，期间不进行平A
```

- 战场推进按固定步长 `STEP_MS = 240ms`（沿用），`0.5s ≈ 2 步`
- 倍速只改「一步对应多少真实毫秒」，不改战斗内时间
- 确定性：同一 seed + 同一操作序列 → 同一结果

### 2.2 平A

```
每 attackInterval 秒，对该单位当前目标造成一次攻击
damage = atk * attackMult * (1 + 平A加成)
```

- 基础 `attackInterval = 0.5`，`attackMult = 0.35`
- 功法可改：`attack.intervalScale`（0.7~1.6 倍时长）、`attack.mult`、`attack.extraHits`
- 平A 不消耗能量，也不需要能量

### 2.3 能量

```
energy += regenPerSec * dt          // 自然恢复，上限 energyMax
regenPerSec 基础 = 1.0
energyMax   基础 = 20
```

- 功法可改 `energy.regen`、`energy.max`
- 四阶起的功法可以**改写来源**：受击回能、击杀回能、平A 回能
- 能量只用于放技能

### 2.4 技能

```js
skill = {
  id, name,
  cost,           // 能量
  castTime,       // 施法时长（秒），默认 0.6
  cooldown,       // 冷却（秒），默认 4
  cond,           // 释放条件，见下
  target,         // frontFoe / lowestHpFoe / self / ally
  effect,         // { mult, hits, pierce, shield, heal, dot, ... }
}
```

释放规则（按顺序判定，任一不满足则不放）：
1. 冷却已好
2. 能量 ≥ cost
3. `cond` 满足（见 2.5）
4. 目标合法

**施法期间不进行平A**，所以放技能有明确的机会成本：`castTime / attackInterval` 次平A。

### 2.5 条件（cond）

只为让技能有「时机感」，不做复杂表达式：

| cond | 含义 |
|---|---|
| `{ routed: true }` | 功法当前贯通 |
| `{ foeHpBelow: 0.5 }` | 目标生命低于 50% |
| `{ alliesHurt: 1 }` | 至少一名队友生命低于 60% |
| `{ energyAbove: 12 }` | 能量高于阈值（蓄力型） |
| `{ attackCount: 6 }` | 自上次技能后已平A 6 次 |

## 3. 数值基准（用于第一轮平衡）

| 项 | 基准 | 说明 |
|---|---|---|
| 战斗时长目标 | 30~60 秒 | 普通遭遇 30s，精英 45s，首领 60~90s |
| 平A 间隔 | 0.5s | 一场 60~120 次 |
| 平A 倍率 | 0.35 × atk | 单次伤害低、靠频率 |
| 能量恢复 | 1.0 /s | 60 秒共 60 点 |
| 能量上限 | 20 | 满槽可连放两个中等技能 |
| 技能消耗 | 8~15 | 一场约 4~7 个技能 |
| 技能倍率 | 1.4~2.6 × atk | 明显高于平A，值得等能量 |
| 技能施法 | 0.6s | ≈ 1.2 次平A 的机会成本 |
| 技能冷却 | 4~8s | 防止单技能刷屏 |

设计意图：**平A 是地板，技能是天花板，能量是两者之间的选择**。

## 4. 功法数据结构

```js
MANUSCRIPTS[id] = {
  id, name, rarity,            // 1~7，对应层数
  desc,
  load,                        // 负荷
  cells, veins, entry, exits, io,   // 已有：占地与纹路
  attack: {
    intervalScale: 1.0,        // 平A 间隔倍率
    mult: 1.0,                 // 平A 伤害倍率（乘在 0.35 之上）
    extraHits: 0,              // 平A 追加段数
  },
  energy: {
    regen: 1.0,                // 每秒恢复
    max: 20,
    onHit: 0,                  // 受击额外回能
    onAttack: 0,               // 平A 回能
  },
  skills: [ skill, ... ],
  tiers: [{ at, name, effect }],  // 覆盖率台阶（已有）
}
```

**稀有度只决定「机制维度」，不直接给数值**。数值仍由 `tiers`（覆盖率）与构件决定。

## 5. 七阶设计（对应七层塔）

| 阶 | 层 | 引入的机制 | 示例 |
|---|---|---|---|
| 一阶 | 1 | 只有平A 加成 | 「疾刺」：平A 间隔 ×0.8，占地 2 格 |
| 二阶 | 2 | 一个无条件技能 | 「裂斩」：单体 1.8×，cost 8 |
| 三阶 | 3 | 技能带条件 | 「守势反打」：贯通时才放，反伤 |
| 四阶 | 4 | 改写能量来源 | 「嗜血」：受击回能 +0.6/s，能量上限 -4 |
| 五阶 | 5 | 技能改写平A | 「连刺」：技能后 3 秒内平A 追加一段 |
| 六阶 | 6 | 双技能 + 独特能量 | 「双流」：两个技能共享冷却，能量双轨 |
| 七阶 | 7 | 改写规则 | 「逆脉」：平A 也吃贯通加成；护盾溢出转伤害 |

一阶功法必须**占地 ≤2 格、负荷 ≤2**，保证任何板面都能塞下——这是招募模板的基础。

## 6. 构件语义（改造）

能量不再「从时钟脉冲灌进纹路」，所以构件的作用改为**调节恢复与转化**：

| 构件 | 新语义 |
|---|---|
| 直导管 | 恢复速率 +0.10/s（纯增益） |
| 弯管 | 无增益（转向用，便宜的填充） |
| 棱镜分流 | 恢复 +0.06/s，且技能消耗 -1（并行两条线） |
| 脉冲储能腔 | 恢复 ×0.6，但每满 10 点自动存成一次「爆发」（下次技能伤害 +40%） |
| 阈值闸 | 生命低于 50% 时恢复 +0.5/s |
| 余烬导管 | 平A 附 1 层灼烧 |

**覆盖率与贯通判定完全不变**——它仍然是「纹路填了几成」，只是效果从「能量能不能流过去」换成「恢复与转化增益」。

## 7. 站位

- 每个单位有身位 0~3（1~4 号位）
- 平攻、招式、纹路倍率和合修被动在四个身位均可用。
- 星火、逐隙每回合至多主动换位一次。回息在敌方攻击后援护前方生命低于 30% 的相邻友军，每回合至多一次。
- 压力 0–49 时按基础速率自然回裕。50–79 时恢复 80%，80–100 时恢复 60%。战斗阵线始终显示当前压力，高压时显示恢复降幅。

---

## 8. 掉落与招募

- **按层掉落**：第 N 层主要掉 N 阶功法，N±1 阶为稀有补充
- 首领必掉一套当前层阶位功法
- 祭坛：用遗物兑换指定阶位功法（保底）
- 招募：一阶微功法 + 2~3 个刻印（构件），保证新角色立刻能打

## 9. 存档兼容

- schema 升到 2：去掉 `weaponId`，加 `manuscript.skills` 等
- 老档（v1）读入时：删除 weaponId，若单位没有功法则发一套一阶微功法
- `plateMode: classic` 保留，老档板面仍是 4×4

## 10. 验收标准

1. 同一 seed 战斗可重放，结果完全一致
2. 无武器系统残留（`weaponId` 在源码里为 0 处）
3. 平A 间隔可被功法改写，实测 0.35~0.8s 生效
4. 能量按秒恢复，技能受能量/冷却/条件三重限制
5. 七阶各有至少一套功法，一阶占地 ≤2 格
6. 招募出来的新角色开箱即可战斗（有功法 + 刻印）
7. 普通遭遇 25~45 秒，精英 40~70 秒，首领 60~100 秒
8. `npm test` 全绿（含新增的战斗时间轴与技能测试）
