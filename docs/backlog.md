**仍可继续的**：风味句的世界观内容打磨（把"画面"写得更具体、与章节/生态呼应）——纯文本工作，改 `flavor.js` 即可，不碰机制。

**四条分层（后续改这块时别打破）**：
1. `data.js` —— 机制数据，不写面向玩家的数字文案

4. `ui.js` —— 只把事实排成「标签 值」，不做计算、不拼数字

### A2. 「接通」与「贯通」是两个机制；台阶改名　`已完成`
**结论**：接通不是「用得少」，是完全没人读——接线模型已按 C 方案整体删除，见 B3。现在只保留「贯通」（蚀刻法入口→出口，×1.15）这一个通路概念。
- **贯通**：蚀刻法自身的入口→出口在金属格上连通（`manuscript.route`），给 ×1.15 乘算。玩家已理解。
- **接通 / 布线**：纹路零件从输入极连到输出极（`circuit.buildGraph` 的 `reachableOutputs`）。

**台阶改名 `已完成`**：全项目统一为「共鸣阶」（`src/`、`tests/` 已无「台阶」残留），术语表条目改为「覆盖 / 共鸣阶 / 贯通」。

**为什么删**：追了一遍发现它比预想更彻底地空转——
1. `reachableOutputs` 算完无人读取；
2. 纹路增益按「端口对齐比例」结算，与是否接到输出极无关；
3. `consumeOutput` / `hasSurge` / `pulse` 没有调用方；
4. 装配校验只查有向闭环，不查是否接到输出极。

玩家侧只剩「自动接通」按钮与画面连线，极易误以为是机制。已按 C 方案（整体删除）处理，详见 B3。

### B4. 术语冲突：可装配的东西该叫「蚀刻法」　`已结案（2026-11-15，见 B13）`
世界大纲里「蚀刻法」是**原理层规律**（纹理如何形成、加深、覆盖、断裂），「功法」才是实践层可传授的实现。现在游戏把 80 门成套路线叫「蚀刻法」，是拿规律的名字当产品名。

**新论据（2026-11-14，用户指出「金属天生、功法才是发下来的」）**：三层各自的可传递性是不一样的——
**金属天生（改不了）→ 功法可发可传（发的就是这个）→ 纹刻不出来（学得会，刻不出）。**
国家能发的只有功法，玩家在工坊里挑/装/卸/换朝向的那 80 门，干的全是「发下来 / 学过来」这件事，所以它必须叫功法；「蚀刻法」没有门数、不能装配，它只能是那本讲「纹为什么长这样」的规律。
详见 `2026-11-14-life-metal-setting.md` §3.1 与 §7。

建议：显示层把可装配的改成「功法」，原理层的说明文字保留「蚀刻法」；存档字段 `manuscript` 不动。
**落地走便宜的半步**：先只改三个高频位置（工坊面板标题、图鉴分类名、词条 `manuscripts` 的解释），别全库机械替换——80 个条目名里有两成本身带「法 / 式」字样，批量替换会出病句。改完跑 `test:ui` 与 `test:etching`。

### B8. 满压临界：裂 / 砺　`已完成（2026-11-14）`
**问题**：压力 0–100，50/80 两档都是**红利**（伤害 +10%/+25%），100 只是封顶。于是最优打法是把压力顶满——压力系统退化成「过用则利」，跟大纲 §4.7「过用则裂」直接冲突。

**已定**（用户拍板走 DD 式的临界判定，但换成我们自己的物理）：顶到 100 的那一刻掷一次，**一人一场只此一次**。

| | 概率 | 后果 |
|---|---|---|
| **裂** | 75% | 纹理方向律反转：满压 ×1.25 翻成 ×0.85，受伤 ×1.25，抛光 ×0.70；**带裂进下一场**，回营地安抚（30 金）才清 |
| **砺** | 25% | 压力退回 50，抛光 ×1.20，不留记录 |

**为什么是「规则变了」而不是「性格变了」**：DD 的 Affliction 是把英雄变成另一个人（狂乱、自残、尖叫）；我们的对应物是物理的——同一条纹，裂了之后方向律反转，红利翻成负担。所以改的是乘算符号，不是给角色贴标签。

**为什么砺要安静**：它不是奖励，是「这次没裂」。不留记录、不弹大标题、不给特效。

**落点**：
- `data.js` · `DESIGN.resolve`（`whetChance: 0.25` / `crack{damageMult,takenMult,polishMult}` / `whet{stress,polishMult}`）
- `combat.js` · `rollResolve()`、`pressureDamageMultiplier(stress, u)`、`energyRegen` 乘 `u.polishMult`、`applyDamage` 受击侧乘 `takenMult`；新字段 `cracked` / `polishMult` / `resolveUsed`；开局就顶满压的人也在 `create()` 里过一遍悬崖
- 复用**早就留着但一直没用**的 `u.affliction` 通道：`buildAlly` 读入、`prepareResult` 带出、`encounter.confirm` 写回角色、`Roster.comfort` 清除。这条链本来就在，只是从来没人往里写值
- `ui.js` · 战斗条「裂」标签与负号伤害、营地角色详情的裂痕说明
- `terms.js` · 词条 `resolve`（显示名「裂 / 砺」），`stress` 词条补一句「顶到 100 触发临界判定」
- `tests/unit/stress-resolve.test.cjs`（6 条）：乘算翻转、两种结果都掷得出、只掷一次、权重是大头、受伤/回裕三条数值落点、带裂下场与结算回传、词条齐全

**遗留**：砺那条「抛光 ×1.20」偏保守，等跑一轮远征看它有没有存在感；裂的 `takenMult 1.25` 与 C4 的防御减伤 80% 会叠乘，若显得过狠，先调 `takenMult` 而不是动防御。

### B9. 负荷预算重构：44 → 20，删负荷返利，接上瘢痕减免　`已完成（2026-11-15）`
**问题**：77 格 × 0.57 = 44 点，而装满 4 门功法加纹路只要 18~22 点。于是「超载转裂纹」在正常局内永远触发不了，§6.4 那套代价等于没写，负荷系统整条空转。

**三处改动**：

1. **两套系数分开**：`DESIGN.capPerCell = 0.57`（经典 4×4 夹具，14 格 → 8 点，尺子不动）／`DESIGN.generatedCapPerCell = 0.26`（异形板面，77 格 → **20 点**）。`Circuit.loadCap` 按 `plate.generated` 分派。
2. **删掉负荷返利**：`manuscriptState` 里「每点负荷 +3% 主修乘算」整段删除，`effects.loadBonus` 恒为 1；`Stats.resonance` 同步去掉那一行，免得界面显示一个结算里没有的加成。理由：返利让重功法自己抵掉成本，方向正好与「过用则裂」相反。
3. **瘢痕减免闭环**：`Circuit.scarRelief()` ——一件纹路每压住一处**激活**瘢痕就少算 1 点负荷，单件最低 0、总负荷永不为负。粒度对得上 `Expedition.inscriptionScar`（每次烙印只留 1 处），工坊显示「瘢痕 −N」。减免只挂在纹路，不挂在蚀刻法上。
4. **补齐战斗口径**：超载每 1 点 → 开局压力 +8、回裕 −0.08/s，新增 **回裕保底 0.1/s**（原本可以扣成负数＝没有出手权，那不是「过用则裂」）。

### B12. 打通「主动超载 → 高压流」　`已完成（2026-11-15）`

**规则改动**
- `DESIGN.overload = { stressPerPoint: 8, regenPerPoint: 0.04, heatThreshold: 50 }`：每点超载回裕罚项 0.08 → **0.04**，压力 +8/点不变。

`applyDamage` 里的 `impact`（单发幅值）取自 `dmg`，而 `dmg` 进函数时**已经被阻抗削过一次** ——
