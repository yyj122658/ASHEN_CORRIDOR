## A. 文本与关键词

### A1. 描述拆字段：数值行 + 风味句　`已完成（结构已就位，内容可继续打磨）`
**已定**：蚀刻法/纹路的描述拆成两部分——风味句（写世界观、气质、画面）+ 数值行（写机制数字）。

**实施结果（2026-11-13）**：
- 新增 `src/veteran/flavor.js`：风味文本唯一入口（蚀刻法 80 条 + 纹路 30 条），**不含任何数字**
- 新增 `src/veteran/stats-engine.js`（`V.Stats`）：从机制数据算出结构化数值事实（`label/value/tone`），不产出 HTML
- `ui.js` 只负责排版：新增 `factLine()` / `runeFactLine()`，5 处渲染点（工坊面板、图鉴卡片、纹路库、档案页、掉落详情）全部改为读引擎
- `manuscriptDetails()` 不再手拼数字；共鸣增幅也走 `V.Stats.resonance()`，与 `circuit` 结算同顺序
- 单测 `stats-engine.test.cjs` 守卫三件事：数值来自字段、风味句禁止出现数字、所有条目都有风味句
- 旧的 `desc` 仍保留在 data.js 里作为兜底（`V.Flavor.*` 找不到时才用），不影响老存档

**仍可继续的**：风味句的世界观内容打磨（把"画面"写得更具体、与章节/生态呼应）——纯文本工作，改 `flavor.js` 即可，不碰机制。

**四条分层（后续改这块时别打破）**：
1. `data.js` —— 机制数据，不写面向玩家的数字文案
2. `flavor.js` —— 风味文本，不出现任何数字（有单测守着）
3. `stats-engine.js` —— 机制数据 → 结构化数值事实（`label/value/tone`），不产出 HTML
4. `ui.js` —— 只把事实排成「标签 值」，不做计算、不拼数字

### A2. 「接通」与「贯通」是两个机制；台阶改名　`已完成`
**结论**：接通不是「用得少」，是完全没人读——接线模型已按 C 方案整体删除，见 B3。现在只保留「贯通」（蚀刻法入口→出口，×1.15）这一个通路概念。
- **贯通**：蚀刻法自身的入口→出口在金属格上连通（`manuscript.route`），给 ×1.15 乘算。玩家已理解。
- **接通 / 布线**：纹路零件从输入极连到输出极（`circuit.buildGraph` 的 `reachableOutputs`）。

**台阶改名 `已完成`**：全项目统一为「共鸣阶」（`src/`、`tests/` 已无「台阶」残留），术语表条目改为「覆盖 / 共鸣阶 / 贯通」。

**为什么删**：追了一遍发现它比预想更彻底地空转——
1. `reachableOutputs` 算完无人读取；
2. 纹路增益按「端口对齐比例」结算，与是否接到输出极无关；
3. `consumeOutput` / `hasSurge` / `pulse` 没有调用方；
4. 装配校验只查有向闭环，不查是否接到输出极。

玩家侧只剩「自动接通」按钮与画面连线，极易误以为是机制。已按 C 方案（整体删除）处理，详见 B3。

### A3. 「普通攻击」在窄 UI 里太长　`已完成（2026-11-13）`
**问题**：四字术语在 208px 左栏（`.ws-left`）把招式效果行挤成两行。实测 1440 视口内容宽 249px，82 条招式效果里有 8 条换行。

**已定规则**：全称优先，短标签只在窄容器里用，且**一个容器只允许一套词**（不能同一屏一半全称一半短标签）。
- `stats-engine.js` 新增 `SHORT_LABELS`（目前只有 `普通攻击 → 普攻`）与 `shorten()`；`manuscriptFacts(spec, { compact: true })` 出窄栏版
- 只缩标签与短句：风味句、蚀刻法名、招式名、数字一律不动
- 落点：`manuscriptPanelBody` 整列（主修说明段、共鸣增幅说明、招式条件/效果、共鸣阶、主修间隔）
- `manuscriptDetails` 里的 `movement.desc`（阵形动作）仍是 `data.js` 原文，`compact` 时补一次 `shorten()`
- 宽处（图鉴、拓本入库、撤离奖励）保持全称

**结果**：1440 视口下 5 条效果从 2 行回到 1 行。1180 窄视口仍有 19 条换行——那是多段效果本身长度，与术语无关，暂不处理。

**守卫**：单测断言全称版不得出现「普攻」、窄栏版不得残留「普通攻击」、短标签表无死词条；e2e 断言 `.ws-left` 整列无全称、图鉴有全称。

### A4. 术语词条抽成数据文件　`已完成（2026-11-13）`
**结果**：新增 `src/veteran/terms.js`（`V.Terms`），三张表同源：

- `BANNED` —— 禁用词 → 替换词 + 原因。用正则是因为要绕开合法长词，如 `金属板(?!面)`

配套 API：`text(id)` / `label(id)` / `shorten(s)` / `audit(s)` / `auditTree(root)`。

- `ui.js` 里那份 `terms` 常量删掉，改成 `term(id)` 直接读 `V.Terms`（tooltip 4 处接入）

- `stats-engine.js` 不再自带短标签表，只转发 `V.Terms.shorten`：引擎决定「哪里用窄版」，不决定「窄版长什么样」

### B3. 整条接线模型拆除　`已完成（2026-11-13）`
**已定**：普通攻击由时间轴驱动、余裕由蚀刻法给之后，「输入极 → 纹路 → 输出极 → 脉冲」这套没有任何读取方，整体删除。
做法（用户拍板：不需要自动连通，也不需要自动铺满）：
- 删 `D.TERMINALS`、`plate-gen` 的派生极、`plate.terminals`
- 删 `circuit.buildGraph` / `reachableOutputs` / 有向闭环校验 / 脉冲全家（`pulse` `token` `emptyRuntime` `outputTokens` `consumeOutput` `hasSurge` `hasEmber` `refund` `route` `portKey`）
- 删 `combat` 的 `runtime` 字段、开局直充 token、战报里的 `energy/charges`
- 删 UI 的端子绘制、外侧连线、`traceVisualFlow` 通电动画、相关 CSS
- **删掉「自动接通」按钮与其 dispatch**；`findSmartConnectLayout` / `findAutoInscribeLayout` 保留但**不再有任何入口**（背包/拼图管理是玩法核心，不做自动铺满）
- 自动布局内部改用 `plateEdgeTerms()` 就地推导的虚拟边界极，只作寻路启发，不进 state、不参与结算
**保留**：纹路的端口（in/out + 朝向）——增益仍按「端口与蚀刻法格子的对齐比例」结算；蚀刻法 io 刀口只服务贯通与画面标识。
**顺带修的 bug**：祝福「导通」的 +2 开局余裕以前只往已删的 token 里塞，从未真正加进 `energy`；现在直接加到开场余裕上。
