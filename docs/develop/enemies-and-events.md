# 敌人与事件

本页记录 2026-11-12 这轮深度设计的口径与实现落点。两个目标：让每一层都有能说清的打法，让每个事件都要付一点真东西。

## 1. 设计口径

- **一个敌人 = 一句能说清的行为 + 一个玩家能反制的时机。** 反制手段必须是现有的：换位、换功法、换击杀顺序、留余裕、留护盾。
- **不靠数值堆叠。** 亚种复用同族的立绘与动作，用色调区分；机制必须完全不同，否则只是换皮。
- **层域决定编成。** 三个层域与料理生态共用同一套划分（余光水道 1–2 / 硫泉阶井 3–4 / 黑炉底床 5–7），保证「打到什么」和「捡到什么」是同一套世界。
- **精英是一个本体加随从**，本体站在最前且更厚；不再是把三个普通怪血乘 0.85。
- **首领有三个**，按开局局数轮换（`stats.runs % 3`），达到 50~55% 生命时进入第二阶段并**追加**招式。

## 3. 战斗机制词汇

敌人技能只允许下面这些字段，全部在 `src/veteran/combat.js` 里实现并有测试：

| 字段 | 作用 |
|---|---|
| `target: frontFoe / lowestHpFoe / backFoe / allFoe` | 选目标；`backFoe` 是这轮新增的后排威胁 |
| `blind: {v, d}` | 命中率直接减 `v`，持续 `d` 回合 |
| `drainEnergy` | 抽走目标余裕（不影响冷却） |
| `stripShield` | 打掉目标当前护盾 |
| `healAllies` | 按攻击力比例治疗所有受损同族 |
| `healSelf` / `selfShield` | 自修与结壳 |
| `onDeathBurst` | 死亡时对全队造成一次伤害并附带 DOT |
| `phaseSkills` | 二阶段追加的招式（免疫重复添加） |
| `disrupt.everyActions` | 每 N 次行动触发一次位移 |

命中判定统一走 `hitChance(actor, target)`，眩光在这里扣。注意 `actionCount` 只在 `beginAction` 递增一次——`enemyTurn` 里再递增会让扰位节奏翻倍。

祝福在这一轮才真正接进数值：`edge` 增伤、`guard` 减伤、`pact` 增伤加压力、`mend` 在层间回复里叠加、`flow`/`scavenger` 沿用原有落点。系数在 `Combat.create` 时折成 `battle.bless`，战斗内不再回查数据表。

## 4. 编成规则

`Data.encounterTemplate(kind, index, floor)`：

- **普通**：本域招牌 + 两员不同的随从（排除招牌后按 `index` 轮转），固定三员。
- **精英**：精英本体（`hpMult 0.95`，`isElite`）+ 第 5 层起两名随从，其余一层一名。
- **首领**：`BOSS_ORDER[index % 3]` + 两名本域随从。
- 只由 `(kind, index, floor)` 决定，同种子可重放；`index` 取 `stats.runs`。

编成改动会连带影响采收：每个物种都要在 `Kitchen.ECOSYSTEM` 有产物，否则确认战利时会崩。这一轮的新物种沿用同族产物，只是文案不同。

## 5. 事件

### 结构

```js
{
  id, title, text, minFloor, maxFloor,
  choices: [{
    id, label, hint,
    need?:    { gold, ingredient, meal, part, hpAbove },
    effects?: { gold, shards, stress, healPct, damagePct, hurtPct, maxHpPct,
                ingredient, consumeIngredient, meal, manuscript, blessing, loot },
    gamble?:  { chance, win: {text, effects}, lose: {text, effects} },
    combat?:  { kind },
    then?:    '另一条事件的 id',
    text:     '结果文本',
  }]
}
```

### 规则

- **不满足门槛的选项禁用并给出同一句原因**（`eventGate`），不是点了才报错。
- **赌局确定性**：用同一个 `rngState` 掷，同一状态重放得到同一分支，可写测试。
- **最后一条选项永远无门槛、无惩罚**：自动模拟与保守玩家靠它收尾。
- **收益必须落到真实系统**：食材进 `run.ingredients`，成菜进 `run.meals`，拓本进 `run.fieldManuscript`，祝福进 `run.blessings`，生命上限进 `run.maxHpModifiers`。行囊变动统一走 `recordPackChange`。
- **事件池按层筛选**（`Data.eventPool(floor)`）；不在 `EVENT_ORDER` 里的事件不会随机出现，只能被 `then` 接出来。

## 6. 扩展指引

**加一个敌人**

1. 在 `Data.ENEMIES` 写一条：`hp/atk/def/spd/hits` 只做同族 ±20% 浮动，机制写在 `skills`。
2. 复用立绘：`sprite` 写 `battle-v3` 里已有的 id，`filter` 给一个色调（`hue-rotate/sepia/saturate`）。
3. 精英加 `elite: true`；首领加 `boss: true` 与 `phaseAt/phaseBuff/phaseSkills`。
4. 在 `Kitchen.ECOSYSTEM` 给产物，否则确认战利会崩。
5. 加进某个层域的 `pool` 或 `elites`，并补 `tests/unit/veteran-combat.test.cjs` 的物种覆盖断言。

**加一个事件**

1. 在 `Data.EVENTS` 写一条，`minFloor` 决定最早出现层。
2. 优先用 `effects` 的现有键；需要新键时在 `applyEventEffects` 里加分支并补测试。
3. 想让事件随机出现就加进 `EVENT_ORDER`；只想做第二段就别加。
4. 保证最后一条选项无门槛；赌局必须只依赖 `rngState`。
