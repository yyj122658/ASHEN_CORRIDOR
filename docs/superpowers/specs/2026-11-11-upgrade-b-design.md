## 5. 确定的玩法规则

### 5.1 队伍、星级与羁绊

- 保留六职业、五元素、四人上场、两份同职业同星合成；最高三星，属性倍率先保留 1/1.55/2.30。
- `team` 为 4 个有序槽位（ID 或 null），0/1 前排、2/3 后排；战斗不再自动按职业重新排序。空槽不能压缩导致后排前移。
- 用左右/上下移动按钮完成重排，拖拽为可选增强，手机与键盘必须能完成同样操作。
- frontFoe 优先存活前排，其次存活后排；randomFoe 的被选权重前排 3、后排 1；背刺忽略前排，按最低生命比例选敌。
- 同元素计数按职业原生元素计算，先不做装备改元素。2/4 羁绊按现有累计总值保留，显示累计效果而非只显示增量。
- 换人提供生效羁绊增减预览；消耗角色优先候补，必须显示姓名、星级、是否上场和退还装备；遣散有明确确认。
- 被动第一版：剑士对半血以下目标伤害+10%；盾卫处于前排时减伤+10%；游侠每第三次自身伤害行动仅该次行动命中+10%（多段全部生效，行动结束失效，不累计）；术士对带负面状态的目标法伤+10%；牧师治疗半血以下目标+15%；刺客首次伤害行动暴击率+15%。伤害行动按整次行动计数，未命中也计一次，治疗/增益/眩晕跳过不计。被动不得重复作用于技能每段之外的意外循环。

### 5.2 战斗与首领

- 逻辑 tick 与 requestAnimationFrame 分开。保留六 tick 一全局回合、行动条阈值 60，速度只影响行动条；1/2/3 倍速只改显示时间，不改战斗计算。
- 每 tick 让所有达到阈值的单位各行动至多一次，按 gauge 降序、slot、稳定 ID 排序；每次行动后检查终局。每个单位一次行动只消耗 60 gauge。
- 技能 CD 统一按自身行动推进：先选择可用技能，行动结束后递减已有 CD，再将本次使用技能设为 cd；cd=2 表示随后两次行动不可用。
- DOT、持续增益按全局回合推进；新状态不在施加当刻衰减。眩晕改为 `skipActions=1`，跳过一次自身行动后移除。buff 有 stackKey、明确叠加/刷新规则。
- `step`固定顺序：①tick+1；②若tick是6的倍数则round+1，先对本tick开始时已存在的DOT按side/slot/施加序号结算，再递减这些状态的剩余回合并移除到期项，再结算存活单位的周期回复；③统一检查终局（双方同时全灭按远征失败）；④存活单位积累gauge；⑤稳定排序就绪队列，逐一行动，每次后检查终局；⑥产出检查点。行动阶段新施加的状态只能从下一个全局回合边界开始计时/触发；不能倒回本tick的回合结算。眩晕跳过的一次行动仍推进已有CD，但不触发伤害行动类被动。
- 均衡：按条件选择治疗/增益/群攻/单体；集火：攻击最低生命比例敌人，低于 35% 才优先治疗；保守：低于 75% 优先治疗，其次缺失的减伤增益，再选攻击。避免重复覆盖仍有效的同源增益。
- 群攻对单个目标降低评分，但首领机制技能不能因此被禁用；多段 randomFoe 每段重新选目标。
- 攻击者/目标死亡后不继续非法行动；反伤、灼烧、吸血的触发链不能递归。
- 回廊守门人：每第 3 次自身行动施放全体碎地；前一次行动结束公开预告；生命首次降至 50% 进入第二阶段，攻击+15%，阶段只触发一次。
- 噬忆者：每第 3 次自身行动施放全队总压力+24 的咆哮（按存活人数分配）；其他行动汲取/诅咒；50% 时进入第二阶段，汲取系数+20%，阶段只触发一次。
- 压力满值仍沿用当前崩溃/美德设定，但战斗中状态改变要重算相关属性而不重置 HP、CD、行动条。先保留现有概率。
- 战斗统计：每人伤害、有效治疗、护盾吸收、承伤、击杀；单列 DOT 归属。结算给出可解释的失败提示（如前排过早倒下、治疗不足），不编造预测胜率。

### 5.3 探索、祝福与结算

- 保留七层；1–6 层每层三条路线，7 层首领。路线显示危险等级、收益类别和确定的特殊代价，不显示虚构胜率。
- 每次进入远征生成 seed；逻辑只用可保存的 RNG 状态，视觉随机独立。
- 每条路线有唯一 nodeId、consumed 状态。节点进入后只有一次选择和一次结算，双击不重复领奖。
- 第 2/4/6 层节点完成后出现三选一祝福，再进入下一层；先处理该节点掉落，再选祝福。该轮祝福不能重复出现已持有项。
- 六个祝福：余烬（攻击+10%）；磐石（最大生命+15%，获得时按生命比例同步）；清泉（治疗+20%）；轻羽（速度+10%）；拾荒（后续金币+20%）；禁忌契约（攻击+20%，后续压力获得量+25%）。均仅本局有效。
- 完成一层才令 completedFloors+1。第七层胜利自动撤离。0 层完成的空手返回不发金币、遗物或进度奖励。
- 战斗收尾唯一顺序：胜利生成奖励并进入 `battleResult` → 点击处理战利品进入 `loot`（无物品则跳过）→ 全部掉落取舍完成后 `finishNode` → 记录完成层 → 按层进入 `blessing` 或下一层 `map`。第七层自动撤离发生在首领掉落处理及完成层记录之后，绝不提前清空run。非战斗节点同样先完成事件，再处理掉落，再完成层。bestDepth以实际完成层更新。
- 常规撤离：带回已持有物品和金币；遗物=战斗已获得遗物+2×completedFloors；通关额外+7，不再按当前所处楼层发奖。
- 战斗逃离：保留 ceil(物品数/2)、floor(金币/2)、floor(战斗遗物/2)，探索遗物按 completedFloors 计，每层 1；通关加成=0。确认框展示本次实际保留/损失。
- 全灭：远征包、远征金币、远征遗物全失；每位参战角色随机丢一件已穿装备，继续保留角色并回营满血；压力沿用原有惩罚。出发前明确写出风险，避免隐藏损失。
- 普通胜利的倒地角色战后以 1 HP 起身，再按统一战后恢复公式结算；地图不保留假死状态。
- 结算一次即清空活动远征并产生唯一 settlementId，恢复/双击不再重复发奖。

### 5.4 装备、仓库与经济

- 三装备位、六品质保留。`item.locked` 仅防出售；升星和遣散退回装备时保留锁定状态。
- 全部掉落来源走 `pendingLoot`：逐件接受/丢弃，满包可替换一件，所有取舍完成才推进；不能同时提前把物品发仓库。
- 商人单独采用购买事务：先选背包空位或替换对象，最后扣金币+标 sold+加入远征包，取消不扣款；本次远征所得金币暂不可在商人消费，文案显示营地钱包余额。
- 仓库支持装备位/最低品质/锁定筛选，品质/战力/最新排序；批量出售仅出售当前筛选集合中的未锁物品，确认显示数量和总价。
- 装备对比以换装后的完整属性差值为准，不能只比 itemPower；明确攻击、防御、生命、速度和特色效果的变化。
- 精良及以上初始 25% 概率产生一个特色词条，每件至多一个：余烬刃（对灼烧目标伤害+15%）、守夜印（战斗开始获得最大生命12%护盾）、回响灯（溢出治疗50%转护盾，单目标盾上限30%最大生命）、追猎符（击杀后速度+10%，最多三层）。现有装备迁移不强制随机重铸。
- 同一角色重复穿戴同名trait按traitId去重，只触发一次；不同trait可共存。守夜印与回响灯共享单目标30%最大生命的总护盾上限。追猎符的三层按角色独立统计并于每场开战清空，不能通过三件同名装备得到九层。回响灯由治疗者持有时触发，护盾给予被治疗目标。
- 第一次通关解锁深入，再通关深入解锁梦魇；常规敌人倍率 1/1/1，深入 HP×1.25、攻击×1.12、金币×1.20，梦魇 HP×1.55、攻击×1.25、金币×1.45；首版不增加掉落品质倍率，避免无上限膨胀。
- 开局160金币、招募基础价、12金刷新、祭坛上限先保留；用模拟与试玩证据再调。空手返回不能重置商店或获得免费招募刷新。
- 记录三类成就（首撤、首通、任一三星）作为长期目标，首版只做展示与解锁提示，不额外发货币。

### 5.5 存档、恢复与导入

- 新 key `ashen_corridor_v2`，结构 `{schemaVersion:2, savedAt, state}`。v2 缺失才尝试 v1；v2 损坏应提示并提供 v1 恢复，不静默抹档。
- 迁移 v1 保留金币、遗物、角色、装备、队伍、商店、升级、战绩；补齐空槽、locked/traitId、设置与难度。保留 v1 原串且不改写。
- 事件使用 eventId/choiceId 对应静态规则，不序列化 fn/pool；商人、待选祝福、待处理掉落都是显式阶段。
- 战斗存档仅保存 ID 引用与纯数据，不保存 unit/ref 双向对象、函数、计时器、Canvas、DOM、AudioContext。保存战斗 gauge、CD、buff、意图、阶段、统计、RNG 与行动队列边界。
- 每次合法操作后、战斗每个逻辑 tick 完成后产生检查点；战斗磁盘写入最多每秒一次；visibilitychange/pagehide 尽力刷新。页面突然关闭时最多回到最后持久化检查点，不承诺绝对零丢失。
- 恢复战斗时先显示“继续远征”并等待点击再启动唯一循环；不能标题页背后偷偷战斗。结算页恢复不能重发奖励。
- 导出下载 JSON；导入先校验 schema、枚举、ID唯一性、引用、数值范围、物品归属和数组长度，再确认替换。失败保持旧档不变，替换前另存最近有效备份。
- 导入名称按文本渲染或转义，不作为 HTML；不执行导入数据中的脚本或任意事件处理器。

## 6. 界面与美术实现职责

详细布局、色板、资源名、裁切和生成清单见美术协议。要点：

- 维持低饱和暗紫石材、冷雾和暖余烬；不是把全页换成一张背景图。
- 营地主视觉+四张职业肖像卡；地图是三张有插画的路径卡；战斗保留像素人物并加入统一背景、敌人意图和可读 HUD；仓库有明显的筛选和对比；结算有收益与复盘。
- 图片无文字、无按钮、无数值；所有可操作元素用真实 HTML。统一 SVG 图标由 coding agent 实现，避免用不同平台风格的 emoji 作为最终主图标。
- 360/390/768/1440 宽度无横向溢出；手机不用 hover 才能读关键信息；触控按钮≥44px；正文≥14px；键盘有焦点；支持减少动画和静音。
- 音效首版可用 Web Audio 合成短音（点击、掉落、暴击、胜负），用户首次交互后初始化；默认低音量，可独立关闭，不加载来源不明音频。

## 7. 技术边界与验收

- 原生 JavaScript+CSS+Canvas，不引入 React、Vue、Phaser 或运行时 CDN。开发测试工具可作为 devDependencies。
- 保留双击 index.html 可运行，也提供本地 HTTP 预览。采用顺序 defer 的经典脚本和 `globalThis.Ashen` 命名空间，不使用需要 HTTP 的 ES module/fetch 作为运行时必要条件。
- 逻辑层不依赖 DOM；渲染不得消费游戏 RNG；画面切换不重复注册事件或启动多份计时器。
- 目标是普通一局约10–15分钟，快速倍率明显缩短；此为试玩校准目标，不能仅靠估算宣称达到。
- 必须交付单元回归、固定种子模拟报告、桌面与移动端截图、浏览器完整远征实测，以及资源加载/降级检查。
- 胜率、时长、性能与“更好玩”都需要记录测量条件，不以一场胜利或语法检查替代整体验证。
