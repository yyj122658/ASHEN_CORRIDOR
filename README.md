# 灰烬回廊 · Ashen Corridor

像素风横版自动战斗，融合「搜打撤 + 刷装 + 暗黑地牢压力 + 自走棋羁绊」。
原生 JavaScript + CSS + Canvas，无框架、无运行时 CDN、无打包步骤。

本项目现在有两个互不干扰的入口：

| 入口 | 内容 | 存档 key |
|---|---|---|
| `index.html` | 原版《灰烬回廊》：职业 / 星级 / 羁绊 / 随机装备 | `ashen_corridor_v2`（自动迁移 v1） |
| `veteran.html` | 新版《老兵回路》：无职业，能力来自底盘 + 主手 + 生命金属回路；遭遇可无限重试 | `ashen_corridor_veteran_v1` |

两个入口共用美术资源与逐帧动画，但**状态、规则与存档完全独立**：打开其中一个不会改动另一个的档。
老兵回路额外接入 `assets/art/veteran-v1/` 的 8 张图（工坊/营火/战史场景、板面底材、四类构件物件图）。

## 老兵回路版（veteran.html）

**核心循环**：营地装配 → 下潜七层 → 每层三选一 → 遭遇战可无限「重新整备」 → 活着撤离才入仓。

- **四位线性身位**：1 号位最靠前。短刃只能在 1 号位出力，长矛 2 号位能贯穿两人，重炮 4 号位更省能量。
- **生命金属回路**：4×4 板面，用直管 / 弯管 / 分流 / 蓄能 / 阈值闸 / 余烬把 `时钟` 与 `受击`
  接到 `主手` 与 `保护`。能量是整数单元，分流不复制、蓄能 4 才发、闭环会被编译器拒绝。
- **行为指令**：条件 + 目标 + 动作，按顺序取第一条合法项，最多 AND 两个条件。不执行时界面会说明原因
  （缺能量、身位不对、没有合法目标）。
- **可逆整备**：敌人、初始种子、检查点在第一次进入节点时固定。打不过就重来，不要钱；
  改身位或指令可能改变出手顺序。
- **营火现场烙印**：把本局捡到的构件直接烙进板面，代价是本局生命上限 ×0.8、压力 +40。
  烙进去的东西仍算本局风险池——撤退时按获得顺序保留一半。
- **老兵保护**：紧急撤退保留一半新收获与全部带入资产；确认败退则失去本局新收获，
  但**不永久杀人、不扒装备**。合格撤离（≥3 层）累计解锁第 3 条指令槽与主手一阶调谐。

详细设计与逐任务记录：`docs/superpowers/specs/2026-11-11-veteran-circuit-design.md`、
`docs/verification/veteran-progress.md`、`docs/verification/veteran-results.md`。

## 运行

**方式一：双击 `index.html`**
不需要服务器、不需要联网，直接在现代浏览器（Chrome / Edge / Firefox / Safari）打开即可。

**方式二：本地 HTTP 预览**

```bash
npm run dev
# http://127.0.0.1:4173/
```

服务器只监听 127.0.0.1，拒绝路径穿越，是只读静态服务。

> 两种方式都能完整游玩。`file://` 下唯一的限制是 Canvas 读取像素会被浏览器拒绝（图片跨源），这只影响自动化测试，不影响画面与操作。

## 存档

- 存储 key：`ashen_corridor_v2`，结构 `{schemaVersion:2, savedAt, state}`。
- 旧版 `ashen_corridor_v1` **不会被改写**，只在首次读取时迁移。
- v2 损坏时不会静默抹档：先尝试用 v1 恢复，都失败则报告 `corrupt` 并保留原串。
- 设置里可导出 JSON；导入会先完整校验（schema、数值范围、ID 唯一性、物品归属），通过后才替换，并保留上一份有效备份到 `ashen_corridor_backup`。
- 战斗每 tick 最多每秒落盘一次，`visibilitychange` / `pagehide` 会强制刷新。
  页面被强杀时最多回退到最后一个检查点，不承诺零丢失。

## B 路线改了什么

**配队**
- 四个固定槽位，0/1 前排、2/3 后排；空槽保留，后排不会前移。
- 支持前后移动与换排，手机和键盘都能完成。
- 换人时有羁绊增减预览；升星材料身上的装备会完整退仓（保留锁定）。
- 六职业被动：剑士斩残、盾卫铁壁、游侠三息、术士蚀骨、牧师怜悯、刺客初击。

**战斗**
- 逻辑 tick 与 `requestAnimationFrame` 分离；倍速只改显示间隔，不改计算。
- 每 tick 所有就绪单位按 gauge → slot → ID 稳定排序，各行动至多一次。
- 技能 CD 按自身行动推进；眩晕改为跳过一次行动。
- buff / DOT 按全局回合结算，不在施加当刻衰减。
- 三种战术真正不同：集火优先最低血量、保守优先治疗与减伤、均衡按局面权衡。
- 两个首领都有大招预告与 50% 转阶段（只触发一次）。

**探索**
- 七层，每层三选一；第 2/4/6 层掉落处理完后三选一祝福。
- 六个祝福：余烬、磐石、清泉、轻羽、拾荒、禁忌契约，均只在本局生效。
- 所有掉落统一进 `pendingLoot`，满包必须明确替换；商人购买是事务，取消不扣款。
- 结算按 `completedFloors` 计算，**空手入场立刻撤离不会得到任何奖励**。

**装备**
- 精良及以上 25% 概率出现特色词条：余烬刃、守夜印、回响灯、追猎符。
- 同名词条按角色去重；守夜印与回响灯共享单目标 30% 最大生命护盾上限。
- 仓库支持部位 / 品质 / 锁定筛选与多种排序，换装对比给出完整属性差。
- 锁定只阻止出售，不阻止装备。

**成长与难度**
- 常规 → 深入 → 梦魇逐级解锁（通关才解锁下一档）。
- 三项成就：第一次回来、回廊尽头、三星。

**修复的旧问题**
| 旧问题 | 现状 |
|---|---|
| 入场立刻撤离可刷遗物 | 按完成层结算，0 层 = 0 奖励 |
| 绝望让治疗变多 | 改为 `healingReceivedMult = 0.70` |
| 腐尸永远只普攻 | 普攻评分压到最低，CD 技能优先 |
| 升星/遣散吞装备 | 删除角色前先完整退仓（含锁定） |
| 商人满包物品直接回仓 | 未选定替换前不扣款，购买必须进远征包 |
| 掉落满包直接消失 | 统一 `pendingLoot`，逐件取舍 |
| 刷新丢失远征 | v2 检查点，可恢复（含战斗） |

## 美术资源

固定路径 `assets/art/v1/`，ID → 路径映射写在 `src/ui/assets.js`，**不 fetch manifest**，保证 `file://` 可用。

当前清单：**18 / 18 ready**（总计约 46 MB 原始 PNG）

| 组 | 状态 | 实际尺寸 |
|---|---|---|
| 场景（camp / corridor / boss-chamber） | 3 / 3 | 1536×1024、2172×724、2172×724 |
| 职业肖像（6 职业） | 6 / 6 | 各 1254×1254 |
| 节点插画（7 类） | 7 / 7 | 各 1536×1024 |
| 首领肖像（gatekeeper / memory-eater） | 2 / 2 | 各 1254×1254 |

加载策略：
- 首屏只预加载 `scene.camp` + 当前队伍 4 张肖像（约 4 MB）。
- 进入远征时才加载两张战场图；进入首领节点才加载两张首领档案。
- 节点插画由 `<img loading="lazy">` 按需加载。

降级链路仍然保留（图片目录被删也能玩）：
- 节点图失败 → 隐藏破图图标，露出渐变底 + 线性 SVG 图标。
- 肖像失败 → 职业色渐变 + 职业首字徽记。
- 战斗背景失败 → 程序化砖墙、石柱与火把。
- 首领档案失败 → 渐变底，机制与预告文字仍完整。

## 战斗逐帧动画（battle-v1）

剑士与骸骨兵使用 48 帧逐帧动画（2 角色 × 4 动作 × 6 帧，8 张图集），其余职业与敌人继续使用程序化像素绘制。

| 项 | 实现 |
|---|---|
| 角色识别 | 我方按 `cls === 'blade'`；骸骨兵按 `enemyType === 'bone'`，不按名字/ID/shape 猜 |
| 资源 | 读取 `assets/art/battle-v1/atlas` 的 `rect / pivot / durationMs`，剑士攻击用 `attack-v2.png` |
| 状态优先级 | death > hurt > attack > idle |
| 多段伤害 | 同一动画未播完不重启，不会反复抽刀 |
| 死亡 | 播完保持末帧，绕开原 `if (!u.alive)` 占位尸体早退 |
| miss | 攻击者继续播攻击，目标不播受击 |
| 暂停 | `dt = 0` 冻结，恢复不跳帧 |
| 倍率 | 视觉时间按 `min(speed, 2)` 缩放，逻辑 tick 不受影响 |
| 刷新恢复 | 按存活状态重新初始化，不重放历史伤害事件 |
| 出手帧 | 攻击第 4 帧触发剑光与音效，**不产生任何数值影响** |
| 降级 | 图集加载失败时整只回退程序绘制，`enemyType` 缺失的旧存档同样降级 |

绘制按每帧 `pivot` 对齐脚底锚点，倒地帧的 `pivotY` 变化被完整使用，不会悬空；透明通道保留，未重新压缩成低精度方块。

## 已知限制

1. **没有真人试玩计时**。10–15 分钟目标只有 tick 推算，没有实测。
2. **没有跑完整 7 层远征的自动化胜率**。模拟只覆盖单场战斗；完整远征需要接入装备/祝福选择策略，本轮未做。
3. **战斗存档恢复未做 UI 层验证**。逻辑层 round-trip 有测试，但「战斗中关掉页面再打开」的端到端路径没有自动化覆盖（e2e 只测了非战斗的刷新恢复）。
4. **音效是合成短音**，只有点击/命中/暴击/拾取/胜负五种，没有环境音与音乐。
5. **敌人只有 6 种模板 + 2 个首领**，长线重复感会逐渐明显。
6. **`file://` 下 Canvas 无法读取像素**（跨源污染），不影响显示与操作。
7. **未做完整的无障碍审计**：有焦点样式、`aria-live` 日志、44px 触控目标，但没有做屏幕阅读器实测。
8. **只有剑士与骸骨兵有逐帧动画**，其余 4 职业与 5 种敌人仍是程序绘制，同屏风格存在差异。
9. **动画显示宽度固定 40 逻辑单位**，未按四人阵容逐个微调遮挡；密集站位时可能轻微重叠。
10. **46 MB 原始 PNG 未做衍生压缩**。接入说明建议的 WebP/AVIF 派生、小尺寸缩略图本轮未做；`file://` 下靠浏览器懒加载缓解，HTTP 部署建议先出一套派生资源。
