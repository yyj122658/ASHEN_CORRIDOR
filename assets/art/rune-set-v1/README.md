## 接入边界

生成图的外边距、单格比例与画面尺寸不统一，仍属待校准原画，不能直接按整张图片宽高映射占格。接入时应先约定统一格距，再对齐/裁切到逻辑 cells 蒙版，避免异形纹章透明包围盒遮挡邻件。manifest 中的 solidBounds 仅供定位参考，不是已经验收的精确切片坐标。

占格、端口、旋转、翻转、输入输出仍以现有逻辑数据为准。刻纹表达已有功能，不引入新玩法；旋转和翻转可复用贴图，不另生成相同原画。直导管、阈值闸、余烬导管同轮廓，分别使用菱形、门闩与火焰刻纹区分。

23578 额外示例及其九宫格配置图保留在 `../rune-23578-concept/`，它是风格示例，不属于当前六种逻辑模板。本轮不扩增任意形状，也不表示所有可能占格组合均已制作。

已做图片解码、alpha 通道与占格中心检查；未做游戏内实际尺寸、旋转后端口对齐或美术与代码联调验收。

## 接入记录（2026-11-11）

原画已校准并接进运行时，改动集中在这几处：

### 1. 切片：`grid/`

由 `scripts/prepare-runes.py` 生成（需要 `pip install Pillow`）：

```bash
python scripts/prepare-runes.py            # 默认 160px / 格
python scripts/prepare-runes.py --cell 96  # 换格距
```

做法：取 **alpha ≥ 64** 的实心包围盒（原画外面有一圈 alpha 个位数的极淡外发光，
按 alpha>0 取会把发光算进去，导致留白、相邻构件拼不上；阈值 64 得到的边界与
`manifest.json` 的 `solidBounds` 逐像素吻合），再按 mask 的列数/行数**精确缩放**到
`列数 × 160` 与 `行数 × 160`。

| 模板 | 格 | 切片 | 体积 | 单格宽高比（未纠偏 → 1.0） |
|---|---|---|---|---|
| straight | 2×1 | 320×160 | 100 KB | 1.229 → 横向压 19% |
| elbow | 2×2 | 320×320 | 154 KB | 1.037 → 基本无形变 |
| splitter | 2×3 | 320×480 | 214 KB | 0.969 → 基本无形变 |
| capacitor | 2×2 | 320×320 | 196 KB | 1.055 → 压 5% |
| threshold | 2×1 | 320×160 | 98 KB | 1.145 → 压 13% |
| ember | 2×1 | 320×160 | 96 KB | 1.267 → 压 21% |

选择精确缩放而不是等比缩放：板面格子是正方形，等比缩放会在异形纹章之间留缝；
压扁最多 21%（直导管那类长条），换来金框能严丝合缝。切片四边均贴边、
每个蒙版格中心都有实心像素，已逐张校验。

合计 858 KB，替换掉的是原来 6 张合计 5.9 MB 的未校准原画。**原画保持不动**，仍留在本目录。

### 2. 渲染：`src/veteran/rune-art.js`

独立模块，不改板面既有逻辑。核心是 `V.RuneArt.image(templateId, {x, y, cell, rotation, mirrorY})`，
返回一个 `<g>`：几何在「格」单位里算，再用 `scale(cell)` 放大到画布尺寸
（矩阵和像素尺寸混用会差一个格距的倍数，旋转 0° 时恰好是单位矩阵，看不出来）。

旋转/翻转不另生成素材，变换顺序与 `circuit.transformTemplate` 严格一致：
**先上下翻转 → 再顺时针旋转 → 最后归一化到 0,0**。
`tests/unit/rune-art.test.cjs` 用 `V.Circuit.layout` 的真实格子逐组合比对
（6 模板 × 4 旋转 × 2 翻转 = 48 组），另在浏览器里校验渲染包围盒与逻辑占格一致。

### 3. 自检页

- `preview-grid.html`：六张切片的单件对齐 + 拼装缝隙检查
- `preview-board.html`：直接在板面坐标系里画（含旋转/翻转 + 端口标记）

两者都是纯静态页，改完素材可以直接打开看，不依赖游戏运行。
